# Проверка прежней схемы модератором

Независимые авторы не получают этот файл до фиксации своих вариантов. Это список проверяемых замечаний, а не изменения исходного ТЗ.

1. В прежней схеме не показан перенос только корневых .py и requirements.txt. В новом ТЗ это принципиально: prompts/config/schemas не должны обязательно загружаться из непереносимых файлов и вложенных модулей.
2. ENV не устанавливает отсутствие MCP и прямое исполнение инструментов скриптом. Нельзя использовать baseline как готовый entrypoint: его импорт mcp теперь явно несовместим с заданным образом.
3. Не отражён полный цикл: отправка модели описаний инструментов и состояния, получение действия/аргументов, их проверка, диспетчеризация и возврат результата модели. Qwen сам код не исполняет.
4. METRIC -> Нет сразу ведёт к резерву. Для неизвестной, но однозначно описанной метрики нужен ограниченный по сроку путь разрешения/проверки адаптера; только после исчерпания допустимого пути оценка остаётся неподдержанной. Нельзя подменять её другой метрикой или обещать поддержку произвольной формулы.
5. SHORTLIST -> CONFIRM -> SELECT -> REFIT выглядит обязательной цепью, хотя обе дорогие стадии условны. Нужны явные ветки пропуска/ошибки и временной допуск, не повреждающие опубликованный CSV.
6. Запись первой резервной модели не должна ждать неограниченного профилирования или полного набора тяжёлых импортов. Вместе с тем confirmation нельзя использовать для обучения резервной модели, если затем он заявляется независимым подтверждением. Подготовка split и минимальный профиль должны быть ограничены и согласованы с ранним резервом.
7. Весь срок, включая startup/TaskSpec/API и финальные проверки, ограничен с начала запуска. Недостаточно поставить gate только перед обучением.
8. Выбор по правильной метрике отделяется от формально допустимого CSV. При неразрешимом target/формате нельзя гарантировать принятие результата; при сбое публикации сохраняется предыдущий артефакт.
9. Обученные во время запуска модели и каталоги можно создавать; запрет переноса отдельных заранее подготовленных весов не является запретом runtime-артефактов. Собственные модели с нуля в ТЗ разрешены при допустимом формате, но схема не должна предполагать неподтверждённую передачу их весов.
10. Права на cgroup, свой Docker image, nested Docker, GPU или изоляцию файлов отдельным пользователем организаторами не заявлены. Watchdog/process group и проверенные рецепты не означают sandbox для произвольного Python.
11. Проверка схемы и списка импортов не является реальным тестом Docker организаторов. Наличие локальной команды docker не предоставляет образ платформы или ключ Qwen.
12. Правила сабмитов относятся к внешней процедуре сдачи. Оценки hidden test и лидерборда не могут быть обратной связью внутри текущего AutoResearch.
