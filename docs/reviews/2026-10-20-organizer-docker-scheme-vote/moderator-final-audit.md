# Финальная статическая проверка модератором

Проверена целая редакция Y-v2, SHA256 `34C235025C27DBFAF9DF4C3A5D747B98AADF52F48DE8B6EE8EB880AC160068A1`, вместе с её правилами в `revision-y-v2.md`. Это оценка проекта, не работающей реализации. Голоса независимых рецензентов хранятся отдельно.

## Прослеженные пути

- Неразрешённый выходной контракт: `C -> RESOLVE -> C` при успехе, конечный `FAIL` после исчерпания. Никакого выдуманного submission при неизвестном формате.
- Ранний результат: `BASE -> PUB` без обучения/target-статистик; `SPLIT` отделяет confirmation до первого fit и target-зависимого профиля. Ошибка первой записи не допускает продолжения как будто файл существует.
- Неизвестная метрика: `M -> RESOLVE -> M` при точном разрешении, иначе только `FINAL -> CLEAN -> OUT` с резервом, без сравнения по proxy и refit неизвестного финалиста.
- Qwen: полные OPENAI_* имена, проверка протокола; штатно недоступный API означает `MODE -> B` с явной локальной деградацией. Неожиданная авария любого шага обрабатывается глобальным handler. Наличие `openai` не доказывает серверный native tools/JSON.
- Исследование: `B -> PLAN -> CHECK -> GEN -> RUN -> EVAL -> LOG`. Журнал не запускает планировщик; новый шаг возвращается через B и обязательный supervisor wrapper. Содержательные программы создаются из разрешённых исследовательских операций, а не из произвольного Python модели.
- Продвижение: после качественной оценки `TEST` создаёт отдельный валидный CSV; только затем `PROMOTE`. Ошибка подготовки/записи сохраняет прежний результат. Статус неуспешного опыта и счётчики ремонта не должны сбрасываться при возврате в LOG.
- Завершение поиска: пустой shortlist ведёт к резерву; непустой — к условному однократному confirmation либо выбору по search-validation. После freeze нет обратного пути в поиск.
- `SELECT` проверяет и атомарно публикует CSV выбранного финалиста до refit. Refit допускается лишь при существующем рецепте и запасе на весь путь; при сбое остаётся опубликованный CSV. Повторной независимой оценки после полного refit нет.
- Супервизор действует также на старте, импортах, API, resolver, retry, predict, публикации и cleanup. Мягкая аварийная остановка идёт в ERR и допускает только ограниченный cleanup, не новое обучение или confirmation.

## Ограничения чтения схемы

Обязательный wrapper каждого узла «Шаг» — часть семантики схемы, подробно зафиксированная автором. Пунктир обозначает глобальный контроль, а не необязательный путь. Нормальная остановка поиска через B оставляет время на необязательные финальные операции; глобальный ERR их пропускает.

Диаграмма использует краткие подписи. Полные условия из таблицы границ 1–14 в `revision-y-v2.md` также обязательны: только данные кейса и фиксированные зависимости, отсутствие runtime pip/Git/внешних скачиваний, только разрешённый Qwen-канал, запрет сторонних pretrained, разрешение своих моделей с нуля без зависимости от неподтверждённого переноса весов, запись в cwd/подкаталоги и /tmp. 30–35 ГБ — ориентир свободного места; 600 рублей относятся к суткам разработки, не запуску платформы. Собственный Docker/root/GPU/cgroup write access не требуются. Технические пределы памяти/потомков остаются best effort.

## Что подтверждено и что не проверялось

Сверены актуальный документ задачи, полный requirement.txt и argv/env-контракт baseline.py. Исходники и три первоначальных предложения проверены по сохранённым хешам без изменений. Базовая структурная проверка Y-v2 нашла 35 узлов, 35 строк связей и ноль ссылок на необъявленные узлы. Это не полноценный Mermaid parser/render test.

Образ организаторов и ключ Qwen не предоставлены. Docker, импорты в целевой среде, API, ML, timeout/OOM, отказ записи и cleanup не запускались. Нельзя объявлять архитектурную ратификацию доказательством качества моделей или успешной работы контейнера. Неизвестные private-контракты не имеют гарантии универсальной поддержки.
